# CutGuard 0.2.2 배포 검증 결과

## 판정

로컬에서 실행 가능한 검증은 통과했습니다. **안정판 배포 검증은 아직 완료되지 않았습니다.** 공개 알파로 제약을 설명하는 것은 가능하지만, Windows와 실제 브라우저까지 검증됐다고 소개할 수는 없습니다.

## 실제로 실행해 통과한 항목

- Python 3.12 / Linux / FFmpeg 6.1.1에서 자동 테스트 33개: 실패 0, 오류 0, 생략 0
- 영상·자막 검사, 손상 파일, 잘못된 설정/JSON, 원본 보존, 검토 파일 연결과 저장, 비교 결과
- GUI 디스플레이 불가 시 오류 안내와 종료 코드 2 반환
- 배포 wheel 빌드, RECORD 파일의 해시·크기 검증
- 별도 가상환경 wheel 설치 후 소스 폴더 밖에서 CLI 실행
- 실제 설치본에 오류 더미 SRT 적용: 예상한 자막 항목 4개 탐지
- 소스 배포본 생성 및 QA·테스트·라이선스 포함 여부 확인
- 더미 자료 결과: 영상 포함 7개 / 정상 0개 (이전 검증 기록 포함)

## 이번에 수정한 문제

- GUI를 시작하지 못할 때 Tcl 오류 추적 내용이 노출되던 문제를 안내 메시지로 처리
- 패키지 라이선스 메타데이터를 SPDX 방식으로 정리
- 소스 배포본에 포함되는 예제 경로와 빠른 시작 명령을 일치시킴
- 테스트 생략도 배포 점검 실패로 처리하는 로컬 검증 실행기 추가

## 남은 실제 실행

| 검증 | 현재 상태 | 준비한 실행 방법 |
|---|---|---|
| Windows Tk 화면→검사 완료 | 미실행 | qa/gui_smoke.py / GitHub windows-gui 작업 |
| Chromium 저장→새로고침→불러오기 | 미실행 | qa/browser_smoke.py / GitHub browser 작업 |
| 실제 OS 파일 선택과 기본 브라우저 열기 | 미실행 | Windows 수동 사용 점검 |
| GitHub Actions 원격 실행 | 미실행 | release-check.yml, ci.yml |
| 현업 영상 정확도·시간 절감 | 미측정 | 편집자 테스트 |

현재 연결된 실행 환경은 Linux입니다. 연결 브라우저는 로컬 파일 URL을 보안 정책으로 차단했으며 우회하지 않았습니다. GitHub 연결 브라우저에는 Sign in이 표시되었습니다. 사용자 PC Chrome 로그인과 연결 세션은 같다고 확인되지 않았습니다. 로그인 없이 원격 CI를 실행하거나, 실행하지 않은 작업을 통과로 표시하지 않았습니다.

## 다음 실행 순서

1. qa/README_KO.md의 실제 Windows·Chromium 검사 실행 또는 저장소 업로드 후 GitHub Actions 실행.
2. 자동 검증이 모두 통과한 뒤 파일 선택·기본 브라우저 열기를 수동 확인.
3. 그 결과와 실제 지원 범위를 릴리스 노트에 기록하고 alpha/prerelease 공개.

새 QA 스크립트는 문법 확인을 마쳤지만 해당 실제 환경에서의 실행 결과는 아직 없습니다. 설정 파일을 만들었다는 사실은 검증 완료가 아닙니다.

GitHub 저장소 생성·코드 업로드·릴리스 발행은 하지 않았습니다.
